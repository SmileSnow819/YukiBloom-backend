# COS 图片存储接入设计

## 目标与范围

让 YukiBloom Go 后端将经校验的内容图片统一存储在腾讯云 COS。PostgreSQL 保存图片元数据，COS 保存图片对象。

本次只接入现有图片库使用的 JPEG、PNG 和 WebP 文件，包括后台上传和现有内容导入命令。不上线 Astro 前端、不部署云服务器、不迁移已有生产数据，也不接入 CDN 或图片处理服务。

## 配置与存储边界

- COS 配置由 `COS_BUCKET`、`COS_REGION`、`COS_SECRET_ID`、`COS_SECRET_KEY` 和可选的 `COS_PUBLIC_BASE_URL` 提供。必填项缺失或公有地址无效时，服务和导入命令应在启动阶段给出中文配置错误。
- 凭证只在 Go 服务和导入命令的服务端环境中使用，不传给浏览器、不写入数据库、不提交到仓库。
- 抽象图片对象保存、公开地址解析和删除操作；COS 存储通过腾讯云 Go SDK 操作存储桶。

## 图片流程

1. 上传和导入仍先在后端读取图片、限制大小、校验真实格式及像素尺寸。
2. 生成随机存储键，将对象写入 COS，再将键和图片元数据写入 PostgreSQL。
3. 数据库元数据保存失败时，删除刚写入的对象；事务型导入回滚时清理本次新增对象。
4. 图片库 API 返回可直接加载的 COS URL，编辑器将该地址写入 Markdown；文章公开 API 根据 `coverMediaId` 查询媒体记录并返回 `coverUrl`。
5. 旧 `/uploads/{key}` 地址不再提供服务；已有内容应更新为 COS 公有对象 URL。
6. 图片删除仍先检查文章、页面和站点内容引用并删除元数据，再删除对象。若对象清理失败，返回稳定错误并在日志记录足够的诊断信息；不得向客户端泄漏密钥、SQL 或内部路径。

COS 存储桶对访客只开放对象读取，不开放匿名写入或列表。写入及删除通过服务器凭证执行，并应遵循最小权限。已有 COS 对象由同一 `storage_key` 与数据库元数据关联。

## 错误与兼容性

- 图片格式、尺寸和大小限制保持不变。
- 上传、图片库、删除及公开图片接口的现有路径和 JSON 结构保持不变。
- COS 网络、凭证、桶名或区域错误作为服务端存储故障处理；用户看到稳定中文错误，详细原因只进入服务日志。
- `COS_PUBLIC_BASE_URL` 可用于 COS 默认域名或将来的自定义域名；生成 URL 时安全拼接对象键。
- COS 配置缺失时服务和导入命令启动失败，不再回退到本地磁盘。

## 运维与验收

- 更新 `.env.example`、Compose 配置和 README，说明 COS 桶访问策略、服务端凭证及部署环境变量。
- 通过配置检查确认 COS 必填项缺失时明确失败，且密钥不会出现在错误信息中。
- 对存储层验证 COS 上传、公开地址、删除、对象失败后的数据库一致性，以及事务导入失败时的对象清理。
- 真实 COS 验收由维护者在自己的腾讯云账号中创建桶、配置最小权限密钥并设置 `.env` 后执行；仓库不保存云账号凭证。
- 现有数据库无需新增迁移；现有本地文件不会自动复制到 COS。切换前需明确安排旧图片迁移或一次性导入。
